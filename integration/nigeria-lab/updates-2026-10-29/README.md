# Nigeria demonstration lab updates — 29 October 2026

These files document and reproduce changes made to the separately deployed Nigeria demonstration lab; they are not automatically installed by the companion kit. Review code, target cluster, hostnames, identity-provider settings, and database backups before use in a staging environment. The scripts require Kubernetes access and lab-specific service names. They make persistent changes and must not be run simply to inspect them.

- `fix-partner-session.py` patches the deployed partner portal's session endpoint to return a clear authentication-required response on a 401. It targets a specific built Next.js chunk and refuses unexpected source content; it is a version-specific lab workaround, not an upstream source patch.
- `deploy-consent-beneficiary-api.py` creates an isolated beneficiary-audience Consent Manager API deployment and service using the existing API's image and environment. `deploy-consent-beneficiary-ui.py` configures the beneficiary OIDC client, UI deployment, service and Istio routing for the demo hostname. It uses the lab's private credentials file at runtime, which is not included. The original staff UI's My Consents link and cache refresh are handled by `link-consent-beneficiary.py` and `refresh-consent-staff-link.py`; both target a specific compiled asset and fail on mismatches. Provision routing and TLS separately for another environment.
- `test-consent-isolation.py` creates temporary identity-provider clients, users and fictional consent records, tests each subject's list and detail isolation, and removes them in a finally block. It changes the target test system and requires a dedicated, authorised test environment; inspect cleanup and permissions before use. Two-subject isolation was previously tested in the demo, not certified for other deployments.
- `nigeria_ocha_lga.json` contains the 774 administrative areas derived from the OCHA Nigeria administrative-boundaries workbook used in the demo. Verify provenance, licence, names and appropriateness before redistribution or production use. `import-ocha-lgas.py` defaults to a read-only comparison and writes a private pre-import snapshot; it mutates the database only with `--apply`. It checks 37 state/FCT parents, matches existing records and refuses conflicts. `verify-ocha-import.py` compares the counts per state against the provided data. Review naming/crosswalk choices and test against a backup before applying. On the demo the import matched six existing entries and added 768; all 37 totals matched the supplied source.

These scripts are a snapshot of lab-specific operational changes, not a complete offline image or a substitute for a tested deployment and restore. Keep database dumps, consent records, identity-provider data, credentials, keys and live cluster manifests private. The online logical backup is consistent per database, but not a coordinated snapshot across all services; file volumes are copied online.
